# 7.62x39 HP stats

## Intent

Change the stats of the 7.62x39 HP round (`Inventory.Items.Ammunition.Rounds.762x39.HP`) through the Likho's Rearmed pak:

* Damage 48 to 52.
* Penetration 16 to 10.
* Piercing level 2 to 1.
* Bleeding chance 10% to 40%.

Weight is unchanged.

## Constraints and assumptions

* Ships in `likhos-rearmed`, which stays a pak-only mod that doesn't need UE4SS. A UE4SS Lua override at runtime is ruled out.
* Only the HP round changes. PS and BP 7.62x39 rounds keep their vanilla stats.
* The cooked assets use unversioned properties. Without a usmap, UAssetGUI leaves every export as raw bytes, so property values can only be read and written with a usmap of the current game build.
* UE4SS generates the usmap in game (its mappings dump key) into `Test_C\Binaries\Win64\ue4ss\`, named after the engine version and a hash, e.g. `Test_C-5.6.1-0+UE5-f6d5f942.usmap`.
* UAssetGUI's command line doesn't take a usmap path. Its last `tojson` / `fromjson` argument is a mappings name, resolved to `%LOCALAPPDATA%\UAssetGUI\Mappings\<name>.usmap`. A path there is silently ignored and the exports stay raw.
* With the usmap, `ID_762x39_PS`, `ID_762x39_BP` and `ID_762x39_HP` round-trip through UAssetGUI byte for byte, so the round-trip check in `pak.ps1`'s `Read-Asset` keeps guarding parsed assets.
* A round's stats live in its item definition, `/Game/Blueprints/InventorySystem/Items/Ammunition/Rounds/762x39/762x39_<Round>/ID_762x39_<Round>` (class `IRRItemDefinition`, in `pakchunk6-Windows.pak`). Its `ItemStats` array holds one entry per stat: `StatModifyType`, `Value` (float), `bModifiable`, `bPersistent` and `StatItemConfig`, a reference to an instanced stat object exported by the same asset (`U_Damage_C_0`, `U_Penetration_C_0`, `U_PiercingLevel_C_1`, `U_Weight_C_0`, `U_ChanceToWound_C_0`, `U_CompatibleItems_C_0`). The stat objects carry no value of their own. Entry order differs between rounds, so an entry is identified by its stat object's class, not its index.
* Bleeding is the exception: the `ChanceToWound` entry has no value, and its stat object's `StatEffect` points at `SGE_Wound_C_0` (class `SGE_IsWounded_C`), whose `BleedingChance` holds it.
* Vanilla values:

  | Round | Damage | Penetration | Piercing level | Bleeding chance | Weight |
  |---|---|---|---|---|---|
  | PS | 68 | 19 | 2 | 10 | 0.0075 |
  | BP | 66 | 35 | 3 | 8 | 0.0075 |
  | HP | 48 | 16 | 2 | 10 | 0.0075 |

* The round's actor `BP_762x39_HP` holds a `BulletComponent` whose `BulletData` has a `BulletClass` and a `BulletDefinition`. `/Game/Blueprints/Bullets/BP_Bullet_762x39` is the only 7.62x39 bullet class, so PS, BP and HP share it.
* Assumption, unverified: the game's hit damage, penetration and bleeding read the item definition's values (most likely through `BulletDefinition`), not only the stats panel. If they come from the shared bullet class instead, keeping PS and BP unchanged requires HP to get its own copy of that class, which changes this design. The first in-game test after the build confirms it.
## Scope

Owned:

* `likhos-rearmed/pak.ps1`: its asset reading and a stat edit stage.
* A new `likhos-rearmed` data file listing the stat edits.
* `likhos-rearmed/README.md`: the change list and the compatibility section.
* `build.ps1`: only where it provides the usmap to UAssetGUI.

Context only: the reclass, clone and retarget stages of `pak.ps1` and their data files, repak and UAssetGUI pinning in `build.ps1`, `publish.ps1`.

## Solution

### Usmap

The usmap is a build input like the game's paks. It is generated by UE4SS in the running game after each game patch and not committed to the repo. A pak build takes the newest usmap in the UE4SS folder, installs it under a fixed mappings name in UAssetGUI's mappings folder and hands that name to `pak.ps1`. The build fails when no usmap exists. Every UAssetGUI call in `pak.ps1` uses it, so the clone and retarget stages parse their assets too. A stale usmap after a game patch shows up as a failed round-trip check in `Read-Asset`. `mod.txt`'s `game_build` note covers it: a game patch means a fresh usmap, a rebuild and a republish.

### Stat edit data

A JSON file in `likhos-rearmed` maps an item definition's `/Game/` package path to its stat edits, following the shape of `clone.json` and `retarget.json`. Each stat is keyed by its stat object's class, without the `U_` prefix and `_C` suffix (`Damage`, `Penetration`, `PiercingLevel`), and maps to the new `Value`. `BleedingChance` is a key alongside them and maps to the value of `SGE_Wound_C_0`'s `BleedingChance`. For this solution it holds one asset, `ID_762x39_HP`, with the four values under Intent.

### Stat edit stage in `pak.ps1`

A stage after retarget reads each listed item definition through `Read-Asset`, sets each listed stat and saves the asset into the stage tree with `Save-Asset`. A stat entry is found through its `StatItemConfig` reference and the class of the export it points at. It fails the build when an asset, stat entry or bleeding effect named in the data isn't found, or is found more than once, so a game patch that renames or restructures a stat stops the build instead of shipping a silently unchanged pak. It logs each edit with the old and new value, in the style of the other stages.

An asset listed in both retarget and stat edit data would be written twice from the game's copy. The stage rejects that overlap rather than chaining the two edits.

### Result

In game, the HP round's stats panel shows damage 52, penetration 10, piercing level 1 and bleeding chance 40%, and hits deal them. PS and BP rounds are unchanged. Uninstalling the pak restores the vanilla values, including for rounds already in the stash.

The README's change list names the HP stat changes, and its compatibility section names `ID_762x39_HP` among the replaced files.

## Tradeoffs

* Pak edit over a UE4SS Lua override: the mod keeps working without UE4SS and applies before any item loads, at the cost of a usmap that has to be regenerated and kept next to the build after every game patch.
* The whole `ID_762x39_HP` asset ships in the pak, so any other mod that replaces it conflicts, and the pak needs a rebuild after every game patch that touches it. This matches how Rearmed already ships the Rattler's assets.
